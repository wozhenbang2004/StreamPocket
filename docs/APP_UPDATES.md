# 应用更新

在“设置 → 高级与关于 → 应用更新”中检查、下载新版本。

## 更新流程

1. 查看版本、大小和更新内容，确认下载。
2. 本页显示真实百分比与已下载/总字节；系统 DownloadManager 处理网络等待和断点恢复。
3. 下载完成自动校验安装包，更新页可见时再复核一次并打开手机系统安装确认，不需另点一次安装。
4. 如需允许此来源，在系统设置中开启后返回即可自动继续；最终安装仍由用户在系统界面确认。
5. 从系统安装返回后检查实际安装版本；若仍为旧版，保留安装包并显示重新安装入口。

这是完整 APK 更新，不是差分或静默安装。切到后台不会自动拉起安装界面；点击下载通知或重新进入更新页会恢复当前任务。取消下载仅删除更新缓存，视频、账号与现有应用不变。取消系统确认后不会反复弹出，可主动重新打开确认。

“打开应用时检查更新”可关闭。开启时，每次冷启动或从后台重新打开应用会在前台稳定后检查一次，只读取 GitHub 公开 Release；应用内切页和屏幕旋转不会重复检查。重新开启开关会立即检查，网络失败不会锁住当天的检查机会，下次打开会重试。

发现的新版本会保存，重新打开后仍可查看；“稍后”仅推迟本次打开期间的提示，下次重新打开仍会提醒。关闭自动检查后不会弹出新版本提示，仍可主动检查、下载和安装。已经开始的更新下载与安装状态继续保留。

## 发行资产约定

客户端从 `https://api.github.com/repos/wozhenbang2004/StreamPocket/releases/latest` 读取非 draft、非 prerelease 的发布，要求同时存在：

- `StreamPocket-arm64-v8a.apk`
- `update-manifest.json`

清单字段：`schemaVersion`（1）、`versionCode`、`versionName`、`packageName`、`abi`、`minSdk`、`apkAssetName`、`apkSize`、`apkSha256`、`signingCertificateSha256`。

包名保持 `dev.streampocket.localtest`，ARM64，minSdk24；版本号必须严格递增，并使用与已安装应用相同的证书。客户端核对大小、SHA-256、包名、版本、最低系统与签名身份；每个版本使用 versionCode 与完整 SHA-256 组成的独立私有文件名。0.3.0 起，复核通过的文件写入独立 PackageInstaller Session，fsync 后回读暂存大小和摘要，再提交系统安装。回调绑定当前发布、会话与一次性身份；旧会话、重复结果和取消后的回调不会替换新状态。系统最终验签与用户确认不可省略。

发行时应同时保留 [应用源码与第三方对应源码入口](THIRD_PARTY_SOURCES.md)。签名私钥不进入仓库或发布资产。

## 旧版安装未升级

从旧版首次更新时，可在 Release 下载 `StreamPocket-0.3.3-arm64.apk`，用系统文件管理器打开并覆盖安装。独立文件与应用内分发包内容和签名相同，不需要卸载或清除数据。

更新页显示 PackageManager 返回的已安装版本名称与编号。“复制安装信息”包含包名、已安装版本、设备系统、已安装签名摘要及本次目标包的版本/大小/摘要，不含账号会话或媒体内容。若系统提示已安装更高版本，保留现有应用，先核对这些实际编号。

进程重建后无法恢复的系统确认会保留主动重试入口；不会在后台自动弹出确认，安装成功以实际包版本与签名为准。
