# 视频浏览与失败恢复 · 2026-11-01

## 0.5.0 · 找回内容与连续观看

视频库的观看入口提供全部、继续观看、未看、已看，并可叠加“仅收藏”；它们与搜索、来源和合集共同过滤。收藏可在视频更多菜单中切换，也可多选处理。观看状态直接使用既有进度与时长，未知时长且已有进度仍属于继续观看。界面的进度徽标和数据库查询使用同一判定，库总数反映全部匹配结果，不只计算已加载的一页。

合集管理支持重命名与删除；多选在当前合集内可批量移出并撤销实际移除的关系。删除合集不删除视频记录或文件；观看进度、标记和剪辑草稿保留。数据库从 v1 非破坏迁移到 v2，只新增收藏字段及对应索引。

播放器更多菜单新增三个入口：

- **播放模式**：单次、单个循环、连续播放，保存选择。连续播放沿用当前库的搜索、观看状态、收藏、来源、合集和日期/来源排序，末项停止；每条视频保留自己的观看进度。
- **音轨与字幕**：读取当前媒体真实可用轨道，提供自动选择和关闭字幕；不支持的轨道不可选。手动选择与自动选择分别显示，切换视频时清除上一条专属轨道覆盖，保留字幕开关意图。本批不包含外部字幕导入。
- **画中画**：Android 8.0+ 且设备支持时，从菜单显式进入；系统小窗提供播放/暂停、下一条及失败后的重试。小窗隐藏完整工具层并持续保存进度，回全屏恢复界面；普通离开播放器仍释放播放资源。不会默认在按 Home 时开启小窗。

库查询保持日期/来源的稳定顺序。当前视频即使在观看后离开“未看”集合，也仍用其原有日期、来源和 ID 作为相邻查询锚点；候选下一条必须满足全部筛选。不增加实时最近观看排序，避免播放检查点改变当前排序位置。

界面继续使用原生 View 与现有 Pocket 控件：封面和视频画面保持主体，观看/收藏入口合并为紧凑筛选，批量整理与播放能力按需展开。当前自动化截图使用明确样例；系统 PiP 与实际媒体播放另由隔离模拟器验收，最终证据见 [TESTING](TESTING.md)。

本轮改动纳入 0.3.2 / versionCode 22；发行信息见 [RELEASE_STATUS](RELEASE_STATUS.md)。

## 本轮要求与实现

| 用户原话与范围 | 当前行为 |

| “视频的话可以支持往下滑，然后就滑到下一个视频” | 播放画面中间区域向下滑，达到阈值后松手播放下一个；短滑和取消不切换。中间上滑仍打开信息，两侧保留原有亮度/音量设置。更多菜单提供“下一个视频”替代入口。 |
| “两列视图，支持三列视图” | 视频库顶栏视图入口可选择双列网格、三列网格、详细列表；保存选择，切换页面、重建和重开后保留。 |

| “网络的问题……权限……文件不存在或解析不出来……提示优化一下” | 区分超时、DNS/连接失败、登录要求、源站拒绝、访问权限、文件缺失、无可用画质、链接不支持、证书和空间不足，给出对应恢复动作；原始详情留在详情层。 |

## 交互边界

下一个视频使用当前视频库的搜索、来源、合集和排序；通过数据库中的稳定顺序定位，不局限于列表已加载的 30 条。到最后一条提示结束，不循环到首条。下载页直接播放的入口使用完整视频库的日期顺序。切换保存上一条进度，异步写入绑定原视频 ID，下一条沿用自己的续播位置与标记。重建恢复当前视频 ID；后台期间取消未完成的切换请求。

采用现有原生 View、Media3、PocketDialog 和同一 LibraryStore / InspectionInbox；没有另建播放器栈或解析队列。三列下重新计算复用卡片的封面高度与字号，保持长标题、时长和元信息可辨。缩小图案与保留点击范围分别检查；背景 Drawable 设置后重新应用内边距，避免实际图案被放大。

失败页沿用“原因就近、操作具体、详情按需”的规则。用户执行重新解析才再次请求源站；权限不足和文件缺失不会显示为普通网络超时，403 不直接断言账号登录失效。任何失败均不自动清除账号或原始文件。

## 验证入口

`Library022UiTest` 检查三列选择/恢复、图案与点击范围；`Player022UiTest` 检查完整 DOWN/MOVE/UP/CANCEL、短滑、下一条、末条、进度与标记身份、重建及后台取消；`LibraryStoreTest` 检查跨分页、相同日期的稳定顺序、来源排序和筛选/合集边界；`BatchDownloadUiTest` 检查失败记录冷启动恢复和原位重新解析；`RecoveryMessagesTest` 检查原因分类及恢复文案。

构建命令、最终测试结果和当前渲染证据见 [TESTING](TESTING.md)。原生 View 与播放器时钟夹具不能代替真机输入、硬件解码或源站联调；本轮没有执行用户手机上的安装或实际播放验收。


## 0.3.3 · 用户实机反馈后的修订

0.3.2 的“画面中间下滑”没有满足实际刷视频体验。本次改用 `CanvasPlayerView` 在真实按钮/进度条之外接管画布触摸，避免控制层的空白子视图吞掉手势。默认普通画面区域都能下滑下一条、上滑上一条；开启亮度/音量手势时仅两侧最外 12% 保留原功能。信息改从更多菜单打开；短滑、取消、缩放平移和控件点击不切片，仍沿用筛选与稳定排序。

`VideoZoom` 使用 Android ScaleGestureDetector，只变换视频表面，范围 1–5×。放大后单指平移，小幅单击仍显隐控制层；复原按钮只在 scale>1.01 时出现。切换视频、转屏时复原，避免上一条的缩放落到下一条。抬起任意一根手指后，剩余手指继续平移保持连续。

播放器更多 → 双视频分屏。默认竖屏上下、横屏左右，也可手动切换。两路独立选择（搜索与分页）、播放/暂停/重播、进度与缩放；禁止同一视频同时占两路，避免进度互相覆盖。默认第一路出声，声音按钮切换后只开一路；共享音频焦点，临时失去焦点时两路暂停，duck期间切换声音保留低音量。后台释放两路播放器；返回通过 Activity result 直接交接第一路位置，避免两条异步数据库队列竞争。设备解码能力不足时给出单路重试/换片入口，不宣称所有设备都能同时播放两路高分辨率视频。

输入控件保留统一外观，同时恢复 editTextStyle、触摸聚焦与 IME 输入连接。不能仅用 setText 或粘贴按钮代替键盘输入验收。

X “No video formats found”仅表明未取得可下载格式，不能从该日志确定是代理故障。有登录会话且默认解析仅缺少格式时，允许一次不带 Cookie 的公开 syndication 请求；登录要求、403、验证、限流和连接失败不走此恢复。结果记录公开访问模式，下载仍使用同一模式；源账号不修改。部分视频成功时保留 yt-dlp 的原 playlist_index，避免选错媒体。截图中的具体链接及用户手机代理环境仍未实网复测。


## 产品文案与信息层级 · 0.3.5

用户反馈：“不要写什么从GitHub检查发布，就是检查更新”“用户不需要知道这些东西”。常用页面写用户结果和下一步操作，不讲发布平台、校验清单、内核、会话、分片或状态机；保留影响用户选择的大小、进度、权限、数据保留和失败恢复信息。任务错误不贴源码和协议细节，原始信息继续按需查看或复制。开源署名不删除，放在关于页的明确入口。

更新页保留版本、进度、更新内容和主要操作；初始状态不重复标题。版本记录和问题信息收进“更新帮助”，版本编号/签名不出现在日常页面。应用内更新说明只呈现功能变化和使用提示，安装、构建、测试、源码等发行说明留在仓库。错误需说明可行的下一步，不把不确定原因写成结论。

账号管理中的 YouTube 提供可选网页登录和定向导入，默认尝试公开可访问视频；不宣称登录后全部可下载。Google 的登录页仅用于导航，YouTube 定向导入仅保存该平台信息；网页登录被平台拒绝时不绕过限制。更新后的原生 View 夹具与回归会覆盖更新页、设置、账号入口和导入状态恢复；它们不替代 Google 实际登录和 YouTube 实网下载。
