# 批量下载与前台剪贴板流程

## 当前开发批次 · 普通文件、预设与恢复（尚未正式发行）

“新建”分为“视频与音频”和“普通文件”，切换保留输入草稿及各条检查任务的类型。普通文件按行粘贴完整 HTTP(S) 地址，签名查询参数不走视频网站的去重与追踪裁剪规则。检查响应名、类型与大小后，点击“下载文件”才入队；它不选画质、不转码，合法零字节文件也可保存。网页、登录页和错误响应不当作下载成果。完成记录按实际类型提供播放或外部打开。

“下载预设”可应用内置画质/音频规则，或管理自定义命名预设、封面/字幕选项及 JSON 导入导出。文件名模板先预览；加入队列时固定媒体、画质和命名快照，之后修改预设不回写已创建任务。普通文件和图集不误套媒体预设；原先勾选部分内容统一设置画质的操作仍从同一菜单进入。

成功保存的内容独立记录到下载归档，移除任务记录不会擦掉归档。再次下载前先在后台查重；有历史记录时可明确选择仍然下载，用于文件已移除或改存其他格式。归档是来源身份历史，文件 SHA-256 则用于完整性，二者不互相代替；不因归档存在自动跳过用户操作。

下载意图区分运行、暂停和取消。重新回到应用时，默认恢复可确认的中断传输，保留任务 ID、等待顺序、保存位置和断点；设置“下载与速度”可关闭此行为。单独暂停、整队暂停、用户取消、旧意图不明、合并/处理或公开保存中的任务不自动重放。强停后遵守 Android 机制，重新打开再处理；这不是开机后无限后台运行保证。普通文件断点会重新核对源文件标识，无法安全确认时保留旧数据并说明下一步。

本批的能力目标、逐项状态和验证边界见 [全面升级基线](DOWNLOADER_BASELINE.md)；原签名正式包发布另见 [版本状态](RELEASE_STATUS.md)。

## 0.5.0 · 下载队列管理

下载页新增整队主控制和“选择”入口。暂停队列会保留已下载的数据，并让等待项及后来加入的任务一起等待；若当前项目正在合并或保存，先完成该项，再停止后续任务。队列暂停状态保存在本机，重建服务不会自动解除。继续队列只恢复被整队暂停的项目；用户单独暂停的项目仍需手动继续。

等待项目的更多菜单提供“下一项下载”和“移到队尾”，调整持久顺序及当前服务队列，不打断正在下载的项目。整队暂停期间仍可排序；恢复后沿用调整结果。已有的继续/重试规则仍将该项目追加到队尾。

多选模式支持按当前任务资格暂停、继续、重试失败与中断、移除停止记录。批量失败重试不包括用户取消项；正在暂停或取消的执行仍需等旧进程退出后才能重新开始。已保存的媒体仍在保存附件时，不允许提前移除其任务记录。

移除记录沿用 5 秒撤销，不删除已保存的媒体；停止记录在等待提交期间被明确继续后，旧移除请求不能擦掉新意图。继续整个队列会先提交当前尚可撤销的移除，避免刚从列表隐藏的任务又开始下载。所有批量命令在执行时重新检查状态，页面上显示的数量不作为未经复核的执行资格。

0.2.12 在现有本地 yt-dlp、账号快照和串行下载服务上增量实现。

## 用户流程

- “新建”接受分享文案、换行或相邻的多个链接。每批最多 100 个不同链接、65,536 个字符，保留输入顺序；重复项合并，无效项计数提示。
- X 的同一帖子别名和追踪参数可以去重，`/video/1` 与 `/video/2` 保留为不同输入。B站分P参数保留；其他网站的查询参数不擅自删除。
- 每次提交均追加至独立解析队列。同一时刻只有一个解析任务，新的手动输入、系统分享或剪贴板接受不会取消正在解析或重试的任务。提交成功后只清空本次输入，未提交草稿不因其他入口或回调而被改写。
- 一条失败不丢掉其他结果；失败项与取消项保留身份，可从“查看队列”逐项重试或移除，也可“重试失败”。重试追加到末尾。取消先等待当前解析器退出，再启动下一项，不能提前把旧进程当作已退出。
- 成功结果积累在“待下载”，保留各自画质选择。用户点击单项“下载视频”或“全部下载”时才创建下载任务；只移除实际入队的结果。待解析、失败项、成功结果和画质保存在本机，重建后恢复；未结束的解析重新排队，已经请求取消的项保持停止。
- MainActivity 为 singleTask，下载通知返回现有界面，避免从播放器另建解析队列所有者。
- 批次先一次性持久保存，再按批次顺序交给现有单线程下载服务。新任务追加至末尾，不暂停、替换当前下载。通知继续对应当前任务；重复入队指令不会改变已经等待的任务顺序。暂停后继续或失败重试，仍沿原有规则排到队尾。

## 本地请求调度

解析与下载的元数据请求共用按平台划分的 FIFO 门禁。X、B站、抖音（含短链域名）分别使用 1.5、1.2、2 秒的最小起始间隔；元数据阶段同平台一次一个，下载进入真实传输后释放门禁，允许继续解析下一条链接。传输任务本身保持全局串行。

匿名 X 解析在既有 GraphQL、syndication、legacy 接口间轮换；有登录凭据时沿用登录路径，不以匿名请求替代。B站与抖音使用原有本地解析器，不添加远端解析站点、代理池、账号轮换或上传会话。

超时与暂时网络错误进行一次有界解析重试，并共享 1.5–24 秒退避；HTTP 429 / 明确限流触发至少 60 秒的平台冷却，不立即换接口继续请求。其他平台不受该平台冷却影响。等待可取消；调度状态属于当前应用进程，进程重建后重新开始。yt-dlp 的传输/分段重试仍有次数上限，并采用指数等待。以上是本地流量平滑与可用接口分配，不保证消除源站限制或提高传输速度。

错误类别依据源站错误，而不是附加的 Cookie 说明或帖子 ID 数字。超时不会提示用户登录失效；限流、登录要求、验证和不支持的内容分别提示。账号主文件仍由 AccountStore 管理，各次请求的快照不回写主文件。

## 剪贴板提醒

主界面在恢复前台且窗口取得焦点后检查一次剪贴板。普通非链接内容、敏感标记和无效链接不出现下载提醒；不读取后台剪贴板，不从内容 URI 拉取文本。支持多个剪贴板条目和批量链接。只保存用于去重的 SHA-256 摘要，不保存剪贴板原文。

发现新的链接后，在底部导航上方显示数量、第一条来源与链接摘要、“查看链接”和关闭按钮。草稿、解析队列和待下载中已有的链接不再作为新链接提醒。点击查看后，用应用内选择面板列出链接，默认全选，可取消部分选择；选空时禁用确认。只有点击“解析 N 个”才追加解析，保留草稿、已有结果和待重试项。解析完成后仍需用户点击加入下载。

忽略或确认后才记录这组剪贴板的 SHA-256；单纯展示、查看或返回不算处理。离开应用后，未处理内容可在下次回到前台时继续查看；已处理的同组链接不再提醒。设置 → 下载管理 → 剪贴板链接提醒可关闭。

## 链接入口体验审查 · 2026-11-01

本轮要求原话：“尤其是识别链接那一块”“识别粘贴板的那个链接”“我没有说你后端逻辑或怎么样，我就说UI UX用户体验这一块”。对象为 0.3.1 / `849a8c8` 的新建下载、前台剪贴板提醒及解析结果衔接；不调整提取器、下载内核或请求调度。

| 审查发现 | 用户代价 | 当前界面规则与验收 |
| --- | --- | --- |
| 剪贴板只显示数量，“加入解析”直接请求源站 | 无法辨认链接，批量不能挑选 | 先看来源和具体链接，再选择；查看、取消不解析，确认才解析所选项 |
| 手动粘贴覆盖草稿，仅读第一个剪贴板条目 | 备注/前一条链接丢失，多条剪贴板被漏掉 | 读取所有文本条目，保留原草稿，去重追加；非链接/超限不改输入并就近说明 |
| 任意非空文字都启用解析，输入提示只有总数 | 明知不能执行仍诱导点击，不知识别了什么 | 本地识别有效后才启用解析，按钮说明数量；批量显示来源摘要，无效输入就近反馈，不触发网络 |
| 提交后空输入表单仍占据上方 | 结果与画质操作被挤下去 | 提交后收起空表单，保留“继续添加链接”和粘贴入口；已有草稿保持展开，不因结果更新而收起 |
| 取消藏在队列面板，主表单中的取消永久隐藏 | 等待时不知道如何停止 | 当前解析链接旁直接提供取消和正在取消状态，沿用原队列取消语义 |
| 提醒刚显示就被记为已读，切到后台后消失 | 还没查看就失去入口 | 只在忽略、确认或手动粘贴后记录处理摘要；看过返回仍可继续查看 |

采用基线：现有自定义 `PocketDialog` / `PocketButton`；审美库 DP-05 渐进披露、DP-06 对象连续性、DP-07 草稿与返回，以及 `stream-pocket-ui-review-20261031` 新建下载案例。选择底部轻提醒加按需展开，避免每次回到前台强制弹层。输入区和结果保留同一页，不增加另一套解析队列。

检查使用离线原生 View 与明确的源站响应 fixture，验证手动粘贴、批量勾选、无效输入、取消、返回、结果收起、草稿保留、小屏深色选择面板，并输出当前渲染图。最终验证结果见 [TESTING](TESTING.md)；这些检查不代表用户手机、输入法或源站解析已实测通过。

## 播放

首帧到达后立即隐藏过渡封面，视频画面与窗口内过渡、控件一起合成。播放期间暂停可选的缩略图预先准备，用户拖动仍可请求预览；暂停时恢复准备。没有可用视频轨或画面启动失败时暂停播放并显示重试入口。

开发验证命令与测试说明见 [TESTING](TESTING.md)。


## YouTube 视频 · 0.3.4

YouTube 使用同一条“粘贴/分享 → 解析 → 选择画质 → 下载队列 → 音视频合并 → 视频库”流程。识别完整视频链接、youtu.be 分享短链、Shorts、嵌入链接及已结束直播的视频地址；无协议的常见分享链接也能识别。同一视频的不同链接按视频 ID 去重，不重复解析或入队。

传给内核的 YouTube 地址固定为单视频 watch URL；移除分享追踪、时间戳与播放列表上下文，不整批抓取频道或播放列表。正在直播或尚未开始的视频沿用现有拒绝规则。显示源站实际返回的画质，分离的视频/音频轨使用现有 yt-dlp 格式选择与 FFmpeg 合并，YouTube 采用兼容下载器与现有分片并发，不引入未经验证的分块参数。

沿用已打包的 youtubedl-android 0.18.1、QuickJS 与 yt-dlp 2026.10.26 / EJS 0.8.0；已核对缓存官方 AAR 的 libqjs.so 及 wrapper 自动设置的 --js-runtimes quickjs 路径，无新增远端解析服务。视频库新增独立 YouTube 来源筛选。公开且无需登录的视频是本版接入范围，账号或年龄限制、访问验证、地区不可用均明确说明；不提供无法使用的 YouTube 账号管理入口。失败链接保留并可重试，限流/网络等真实错误优先于日志中的解析警告。

离线 URL、元数据、持久化、原生 View 和队列测试证明应用接线；不代表 YouTube 源站实时可用性、用户网络或 Android 设备上的真实解析下载已验证。

## 0.4.0 · 近期解析、图集与可选附件

解析结果保留 5 分钟，最多 16 项且总密文不超过 8 MiB。完整媒体数据在进程内用临时 AES/GCM 密钥保存；任务只保留不透明句柄。请求临时 info-json 位于应用私有缓存，权限仅当前应用，执行结束后删除。进程重建、超时或账号 revision 变化时回到原链接解析；不把长期 CDN 地址作为任务原始身份。

Cookie 快照与 scope 在同一账号锁内形成。复用时比较请求实际 scope 与当前 scope；保存、清除、暂停和通用 Cookie 导入均使相关旧数据不可用。HTTP 403/410 或明确格式失效才进行一次有界刷新，刷新只接受同作品 ID。源站限流、验证和权限错误不触发反复换接口；刷新期间释放运行时读锁，保持“来源门禁 → 运行时锁”的次序。

账号展示“未验证”“最近请求成功”“需要重新登录”，不把 Cookie 存在或公开内容成功当作账号权限证明。现有任务快照不会覆盖主会话或重建已清除信息。

小红书的 normal 笔记与抖音 images 帖子输出专用图集。每帖最多 100 张，原始张数独立保留，不接受处理后缺项成为完整图集；下载后检查图片识别与 PNG/WebP/JPEG 结束/长度标记，再按原序打包为以帖子标题命名的 ZIP，从下载记录用外部应用打开。图集不进入视频库。

视频的“字幕与封面”默认关闭；有可用数据时才可选。字幕默认选中文，其次英文，其次源站返回的其他语言；排除 live_chat。成功媒体先完成保存，附件逐项提交并立即持久化 URI，后续失败保留成功附件和警告，可从任务更多操作打开。媒体缺少完整附件不误报为整条视频下载失败。保存前进行媒体轨道、时长、MP4 顶层 box 长度检查；

“展开合集并选择”是独立显式操作，仅支持 YouTube 播放列表与 B站分P，每次前 100 项。列表没有体积数据时明确写“大小待解析”，不虚构预计值；选择后仅进入现有解析队列，再选择画质并主动下载。选择为空不可确认，返回不接收任务。批量设置仅作用于勾选项，图集和不适用的音频目标保留原设置。
