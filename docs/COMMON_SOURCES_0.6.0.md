# 0.6.0：常用来源、字幕与下载可靠性

## 本轮目标

基于 0.5.1（主线 `841b545ce57e94e81ecc5288b56926fe2f3041e3`）增量开发。用户希望吸收 OmniGet 的常用来源覆盖和实用下载能力，不以通用提取器的站点数量作为产品完成度。

本轮继续使用 Android 本机 yt-dlp、现有队列、账号隔离、自定义面板和视频库。没有引入新的下载服务器、gallery-dl、Rust 下载引擎或并行应用壳。安装包身份保持 `dev.streampocket.localtest`，当前开发版本为 `0.6.0 / 33`；正式覆盖升级仍要求原签名。

## 新增六个常用来源

| 来源 | 本轮接入范围 | 具体处理 |
| --- | --- | --- |
| 微博 | 视频帖、移动版帖子、明确的视频播放地址及分享短链 | 保留 `fid`、`tabtype`、`layerid` 等内容选择参数；新增独立 Cookie 存储。 |
| 西瓜视频 | 常见单条视频地址 | 保留完整地址和 `id` 等参数；与抖音的账号凭据分开管理。 |
| AcFun | 单条视频地址 | 来源识别、分享入口与独立账号设置接入现有提取器。 |
| Reddit | 视频帖子与分享地址 | 规范化已知域名别名；实际视音频选择仍交给内核，不把无声视频直链当作完整成品。 |
| Vimeo | 普通视频、播放器地址及带权限参数的视频 | 保留路径隐私 hash、`h` 和其他授权参数，不把私密视频地址粗暴缩成数字 ID。 |
| Twitch | Clips、已结束且可访问的 VOD | 支持常见 `/videos/`、`/<channel>/v/`、`/<channel>/video/`、`go.twitch.tv` 及明确视频嵌入；拒绝频道/直播入口。解析后的直播状态仍需再次检查。 |

已有来源及未知站点的通用解析入口继续沿用。来源识别不等于该站所有内容均可下载；账号权限、地区、验证码、平台变更和源站访问限制仍会影响结果。本轮没有承诺 DRM 内容、直播录制、批量抓取主页或付费内容解锁。

请求 URL 与比较用身份分开：去重可以忽略明确的营销参数，但用于下载的首个完整 URL 保留原查询字节、重复参数和权限信息。Vimeo 不同隐私 hash、微博不同内容选择、Twitch 不同时间/权限参数不会误合并。

## 账号升级与状态表达

- 新迁移标记独立于旧版 `channels038.migrated`，升级用户的旧 `other` Cookie 能重新按六个平台分流。
- 已有独立会话、更新后的密文、停用状态和清除记录优先；旧 `other` 及其备份不能复活已删除或停用的账号。
- Reddit、Vimeo、Twitch 仅识别上游实际使用的 Cookie 名称，并校验适用主机、路径、非空值及过期时间。这是本地凭据存在性检查，不是服务端验活。
- 微博、西瓜、AcFun 暂无本轮核实的通用登录成功标志。允许用户在官方网页确认后手动保存 Cookie，界面明确显示“登录状态未确认”，不会把游客 Cookie 说成登录成功。
- Cookie 仍只保存在本机，使用既有加密、平台隔离和每请求快照机制。

## 字幕完整流程

### 下载选择

“字幕与封面”继续使用原有自定义面板，新增逐步展开的“字幕语言与来源”入口。可多选语言，并选择优先平台字幕、仅平台字幕或仅自动字幕；默认仍只选一个优先语言，不自动下载所有语言。

平台 `subtitles` 与 `automatic_captions` 是来源分类，不能证明每条平台字幕均由人工编写，所以界面使用“平台字幕”。语言来自实际元数据并校验为语言标识，不接受通配符或命令片段。空字幕列表和直播聊天不会出现在选项中。

选项先保存在面板草稿，外层“应用”后才写回解析结果；关闭外层面板不保存草稿，也不会触发下载。旧队列的单语言字段继续兼容。

### 视频库与播放器

- 视频库 v3 新增视频—字幕关联表，以已有任务映射绑定，不通过相同文件名猜测关联。
- 下载完成视频先入库、字幕稍后保存时，会补齐附件关联。
- 已完成任务被清除前，旧版附件元数据先持久化到视频库；保存失败则保留下载记录。
- 字幕随保存目录迁移更新 URI；中断后出现新旧 URI 的情况需要幂等合并，避免重复恢复卡住。
- 播放前检查本地 URI、读取权限、大小和格式；首选字幕不可用时选择下一份可读字幕。运行时只对确认属于外挂字幕的错误降级，视频错误保留原反馈。
- 播放器继续使用现有字幕菜单，区分已下载与内嵌字幕。删除视频记录只删除关联，不自动删除用户文件。

## 兼容 MP4 选项

仅在源站元数据确实存在 H.264 视频和 AAC 音频的可用组合时，提供“兼容优先 · MP4”；已知无声 H.264 视频可以单独提供无声选项。

此模式选择并封装源站流，不新增强制转码；最高分辨率取决于源站兼容轨道。无法满足时不会偷偷回退为 AV1、HEVC 或 Opus，却继续标成兼容模式。原最高画质、各分辨率和仅音频选项保持原顺序。

## 跨进程冷却

平台限流与网络退避写入小型本机日志，重启后恢复剩余等待时间。同进程等待仍使用单调时间；墙钟仅用于恢复，异常/过期记录丢弃，最长恢复 60 秒。成功后清除失败记录。

记录只包含平台或主机、时间和失败次数，不保存完整链接或凭据。未知主机状态有容量与闲置期限；慢存储不持有队列准入锁，写入失败降级为内存调度。原平台间隔、FIFO 与取消检查继续生效。

### 正式发布状态

0.6.0 的代码与 CI 构建已完成，正式签名更新包尚未发布。已找回既有签名备份，并从当前 0.5.1 公开发布记录核对原证书摘要；本次环境中仍缺少该备份的原签名参数，尚不能核验其内部证书或签名新版。备份保留在项目外的私有位置，不进入仓库。
